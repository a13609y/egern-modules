# PingMe 自动化任务（签到 / 看视频奖励 已拆分）

PingMe 每日签到 + 看视频得奖励，两件事拆成两条独立定时任务，cron、超时、开关各自独立，互不影响。

订阅地址：

```
https://raw.githubusercontent.com/a13609y/egern-modules-hub/main/rules/pingme/pingme.yaml
```

## 三个脚本

| 脚本 | 触发 | 作用 |
| --- | --- | --- |
| `pingme-capture.js` | `http_request` 抓 `api.pingmeapp.net/app/queryBalanceAndBonus` | 把账号参数存进 `pingme_accounts_v1`（多账号，同一账号重复抓只更新） |
| `pingme-sign.js` | `schedule`（签到 cron） | 只做签到 |
| `pingme-video.js` | `schedule`（看视频 cron） | 只做看视频得奖励（每次循环 5 个视频） |

两个任务彻底分开：cron 各一个、开关各一个、失败互不影响。

## 模块设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 禁用账号抓取 | 关 | 抓包装好后正常用不要再开 |
| 关闭自动签到 | 关 | 打开 = 只跑看视频奖励 |
| 关闭看视频奖励 | 关 | 打开 = 只跑签到 |
| 签到 cron | `30 * * * *` | 全天每小时第 30 分触发，见下方「签到逻辑」 |
| 签到超时 | 300 秒 | |
| 看视频 cron | `20 20 * * *` | 每天 20:20 跑一次 |
| 看视频超时 | 300 秒 | |

## 签到逻辑（按每账号上次确认成功的时间戳排 24 小时）

PingMe 服务端是按「距上次签到是否满 24 小时」判定的，不是按自然日。所以脚本也用同一套尺子：

- **不再有「滚动签到小时 / 目标时刻」**。旧版每天推进一小时目标时刻，再把「过了今天目标时刻」当闸门，
  这套逻辑已全部删除：脚本不看今天是几点、也不做任何固定时刻（如 4:30）的等待。
- **24 小时闸门**：每个账号单独记「上一次服务端确认成功的时刻」（毫秒时间戳，键 `pingme_sign_last_ok_v2`）。
  本次触发时距该时刻**不足 24 小时** → 直接跳过、不发任何请求；**满 24 小时**或从来没有成功记录 → 发签到请求。
  跨午夜也照样成立：23:30 签成功，第二天 0:30~22:30 全部跳过，23:30 才再签。
- **什么才算成功**：`checkIn` 必须 **HTTP 2xx** 且响应是 **JSON**、`retcode === 0`，才写成功时间戳。
  写入用的是**本地收到成功响应那一刻**（略晚于服务端受理时刻，宁晚不早，保证下一次一定落在服务端 24h 之外）。
- **什么不算成功（绝不写时间戳，留待下个整点重试）**：
  - HTTP 非 2xx（500 / 502 等）；
  - 响应不是 JSON（网关 HTML、空响应等）；
  - 网络层失败（超时、连接被重置、stream closed 等）；
  - 业务失败 `retcode !== 0`——包括「距离上次签到未满 24 小时」「今天已签到」这类文案。
    **「已签到」只是服务端文案，不是可验证的成功凭据，不拿它当成功时间依据**，因此下一次仍会正常重试。
- **默认 cron 为什么是每小时一次**：`30 * * * *` 是 24 次/天触发，但每个账号自带 24h 闸门，
  绝大多数触发都是「跳过」，只有满 24h（或上次失败）的那次才真正发请求 —— 结果是每账号每天签一次，
  且某个整点失败时下一个整点会自动补试，不会再像旧版那样被一个错误的「今天已处理」标记卡死整天。
- 每个账号独立判断、独立记录，互不影响；返回「已被注销」的账号会自动从账号仓库移除（与原版一致）。
- 抖音/看视频相关逻辑**未改动**，仍在 `pingme-video.js` 里，由 `CRON_VIDEO` 独立调度。

## 从旧版升级（`pingme_sign_last_run_v1` 迁移策略）

旧版用的是 `pingme_sign_last_run_v1`，值和真实成功没有可靠对应关系：它记的是「今天已经发过请求 / 收到过响应」的
**自然日字符串**（如 `{"a1":"2026-7-14"}`），业务失败、HTTP 错误、甚至没拿到响应都可能留下它。

因此新版本：

- **不读旧键**，也不把它换算成时间戳 —— 它的日期字符串不构成可信的成功时刻，按它判断只会继续误判。
- **不删旧键**：旧键原样保留在存储里（不迁移、不改写），对运行没有影响，你想清理可以手动删。
- 新键 `pingme_sign_last_ok_v2` 单独记录毫秒时间戳，**首次运行没有 v2 记录 = 立刻签一次**，
  所以旧版留下的错误日期标记不会挡住升级后的第一次签到，也不会因为「昨天其实是失败的」而多等一天。
- 账号仓库 `pingme_accounts_v1` 不变，**旧版抓到过的多账号不用重新抓包**。

## 为什么签到 cron 是每小时一次而不是每天一次？

`30 * * * *` 看起来是 24 次/天，但每次触发都会先过每账号 24h 闸门，不足 24h 的账号直接跳过不发请求，
所以实际每账号每天只签一次，同时顺带兜住「设备那个整点没被唤醒 / 服务端临时拒绝」的情况。

想改成「每天固定一个时间跑一次」也可以，比如 `35 20 * * *`，代价是那一分钟设备没醒就顺延到下一次触发，
而每小时一次基本不会漏。

## 看视频逻辑（与旧版一致，未改动）

- 每账号：查余额 → `videoBonus` 循环 `MAX_VIDEO = 5` 次（首次 1.5 秒后开始，之后间隔 `VIDEO_DELAY = 8000` ms，
  每次都用新生成的伪造 `uniquedeviceid`）→ 再查一次余额。
- 中途返回业务错误（如「今日视频奖励已达上限」）立即停止当次循环。
- 账号返回「已被注销」会自动从仓库移除。

## 抓包 / 使用顺序

1. 装模块 → 打开 MITM（`api.pingmeapp.net`）→ 打开 PingMe App 进一次「余额/奖励」页面触发抓包，收到「✅ 新账号已入库」即可。
2. 之后不用再打开 App，定时任务会在 Egern 运行期间自动跑（App 被杀时错过的那次，下一次触发补上）。

## 兼容说明

- 账号仓库键沿用 `pingme_accounts_v1`，**旧版抓到过的账号不用重新抓**。
- 也兼容单账号的 `pingme_capture_v3` 键（旧签到脚本时代抓的），仓库为空时自动回退读取。
- 签到成功记录改用 `pingme_sign_last_ok_v2`（毫秒时间戳）；旧的 `pingme_sign_last_run_v1` 不再读取（见上方迁移策略）。
- 模块/脚本由 `script_url` 从本仓库 `main` 分支拉取，Egern 对远端脚本存在缓存（缓存时长未经验证）。
  升级后若发现日志里仍是旧版文案（例如「今日目标签到时间」），可尝试删除该模块重新导入以强制拉取最新脚本；
  这只是一种可选的排查手段，并不是必须步骤。
