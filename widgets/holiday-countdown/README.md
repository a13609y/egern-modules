# 节日倒数（Egern 小组件）

距离下一个节日还有多少天 · 数据内置到 2050 年，不联网 · **按画布实际大小自动决定放几条**，不会再溢出裁切。

## 这次是怎么保证不溢出的

布局不是写死字号，而是**先看画布能放多少，再决定放几条**：

1. 从 `ctx.size` 读真实宽高（读不到时退回小号 155、中/大号 329×155 / 329×345）。
2. 扣掉内边距、头部、大数字块，得到格子可用高度。
3. 行高按 `字号 × 1.5` 估（iOS 中文字形的实际占位），每条格子两行文字。
4. `行数 = 可用高度 / (格子高 + 行距)`，能放几行就放几行，剩下的条目直接不渲染。
5. 所有 text 一律 `maxLines: 1` + `minScale`：宁可缩字，绝不换行撑高。

这套做法是照搬 lylywayr / jnlaoshu 的「时光倒数」（同样是 Egern 脚本，真机跑了很久），我只是把数据源换成了自己的节日表。

结果（按 155 / 329×155 / 329×345 的画布）：

| 尺寸 | 列数 | 列表条数 | 用掉高度 / 画布 |
| --- | --- | --- | --- |
| 小号 | 2 | 2（节日名 → 圆环 → 数字 → 2 条） | 149.5 / 155 |
| 中号 | 1 列 | 5（左侧大圆环，倒计时在圆环右下，右侧列表天数右对齐） | 151 / 155 |
| 大号 | 3 | 9（格子带日期副标） | 302 / 345 |

hero 区（圆环 + 右侧大数字 + 节日胶囊）的高度是**写死的预算值**（中号 62、大号 96），不再用「圆环直径 + 间距」推算——那样会把中号的列表全吃光。

`test.mjs` 里有一条用例会把 155×155、158×158、170×170、329×155、338×158、329×345、338×354、345×354 全跑一遍，断言都不溢出；另一条断言**所有 text 都带 `maxLines: 1`**（否则第 3 步的高度估算就失真了）。

## 显示什么

- **法定与传统**：元旦、春节、元宵、清明、劳动节、端午、七夕、中秋、重阳、国庆、除夕
- **二十四节气**：小寒 → 冬至，共 24 个
- **现代节日**：情人节、妇女节、愚人节、青年节、表白日(5/20)、儿童节、教师节、万圣夜、光棍节、双十二、平安夜、圣诞节、跨年夜、母亲节、父亲节、感恩节
- **自定义纪念日**：`名字=05-20` 每年循环，`名字=2026-02-01` 只算一次

按「还有几天」升序，当天显示「今天」。配色：节气绿、现代节日金、传统节日主色、当天红色。

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `TITLE` | 节日倒数 | 标题（小号用节日名代替） |
| `TRANSPARENT` | false | 不画背景渐变，只留一圈极淡描边 |
| `THEME` | auto | auto / fest / weekend / workday |
| `GRID_ITEMS` | 0 | 0 = 按画布自动算；填数字则强制上限 |
| `SHOW_TERMS` | true | 是否显示二十四节气 |
| `SHOW_WESTERN` | true | 是否显示现代节日 |
| `ANNIVERSARIES` | 空 | 自定义纪念日 |

## 数据从哪来

**完全不联网**：农历节日表 2024–2050（lunardate 生成）、二十四节气表 2024–2050（cnlunar 生成）、固定公历节日现算、母亲节/父亲节/感恩节按「第 n 个周几」现算。

## 文件

- `holiday-countdown.yaml` / `holiday-countdown.js` —— 模块本体
- `test.mjs` —— 14 条用例（含防溢出矩阵、maxLines 断言、数据正确性、主题、透明模式）
- `gen-preview.mjs` → `preview.html` —— DSL 转 HTML 的近似渲染。**注意**：预览按 1.5 行高和 nowrap 渲染，仍不等于真机，只用来大致看结构
